# Fresnel

המונורפו של מדור Fresnel (מדור תמונת מצב, ענף מגדלור): backend משותף, ה-frontends של הצוותים וה-DB.

| תיקייה | מה יש בה | בעלים |
| --- | --- | --- |
| `api/` | backend משותף (fresnel-api): מודול shob ומודול vandamme | שו״ב + ואן דאם |
| `web-vandamme/` | frontend של ניהול אירוע | ואן דאם |
| `web-shob/` | frontend של השו״ב | שו״ב |
| `mobile/` | אפליקציית ניהול אירוע מובייל | מובייל (בן נתנזון) |
| `db/` | `schema.sql` ו-migrations, schema `fresnel` | ואן דאם |

## ניהול אירוע (ואן דאם) – האפיון בקצרה (14/10)
- השו״ב שומר ב-DB כל נרטיב שדורון שולח (טבלת `narrative`). נרטיב עם `is_anomaly = true` הוא אנומליה – מומלץ לפתוח עליו אירוע. לכל נרטיב יש `embedding` לחיפוש בשפה טבעית.
- השו״ב פותח אירוע על נרטיב, והאירוע מופיע בניהול אירוע. כותרת, תיאור, זירה וזמן זיהוי נלקחים מהנרטיב ולא נשמרים פעמיים. אין אירועים בלי נרטיב.
- נתוני מעורבות (פרסומים, צפיות, שיתופים, מקורות) משתנים כל הזמן, ולכן נשלפים מדורון ולא נשמרים.
- במסך האירוע: תיעוד פעולות שבוצעו, לשונית אקינטור, ופאנלים "ניטור אירוע" ו"מקורות מידע".
- פעולה היא תיעוד בלבד של מה שכבר בוצע: סוג מבנק הפעולות (dropdown), כותרת עד 100 תווים, תיאור עד 500. **אין צאט ואין אישורי פעולות.**
- האייטמים לא נשמרים אצלנו: שולפים אותם מדורון לפי `narrative_id` של האירוע.
- שיחות אקינטור לא נשמרות אצלנו.
- סטטוס אירוע: פתוח → בטיפול → סגור. אירוע סגור אפשר לפתוח מחדש.
- אמת / תרגילית: מערכת הסימולציות של אושר יכולה לשלוח אירועים מהעבר. הם נשמרים עם `is_simulation = true` ומצביעים על הנרטיב המקורי, ומקבלים `event_id` חדש שחוזר ב-response.
- DB (גרסה 0.6): 5 טבלאות ב-`db/schema.sql` – `narrative`, `event`, `action_type`, `action`, `event_log`.

פיגמה: https://www.figma.com/design/kk7LQbGpv8rm9OAYr7fTG8 (המסכים עדיין מציגים צאט ואישורים – האפיון למעלה גובר).

## עקרונות
- כל job ב-CI רץ רק כשמשהו השתנה בתיקייה שלו.
- כל צוות מאשר שינויים בתיקייה שלו (CODEOWNERS).
- שינוי ב-DB רק דרך migration ב-`db/`.
- ערכים קבועים (סטטוס, זירה, חומרה, סוג רשומה בלוג): קוד באנגלית ב-DB עם CHECK, והתווית בעברית רק בקובץ קבועים משותף ב-UI. רשימה שמשתנה בזמן ריצה (בנק הפעולות) – טבלת קודים. בלי עברית ב-DB ובלי ENUM של PostgreSQL.
